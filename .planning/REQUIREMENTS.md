# Requirements: LLM Wiki

**Defined:** 2026-04-10
**Core Value:** A Copilot librarian that ingests any source, integrates it into a structured wiki, and answers questions from accumulated knowledge — so the wiki gets richer over time instead of starting from scratch on every query.

## v1 Requirements

### Schema

- [ ] **SCHEMA-01**: `copilot-instructions.md` defines librarian role, directory structure, naming conventions, and operation trigger phrases in ≤ 2 pages
- [ ] **SCHEMA-02**: Schema includes an explicit prohibition list (never modify raw/, never edit past log entries, never write without checking index)
- [ ] **SCHEMA-03**: Schema includes pre-write contradiction check as a mandatory ingest step
- [ ] **SCHEMA-04**: `AGENTS.md` at repo root mirrors copilot-instructions.md for cross-vendor compatibility (Claude, Gemini, Codex)

### Wiki Structure

- [ ] **WIKI-01**: `wiki/` scaffold contains index.md, log.md, overview.md, and empty subdirectories (entities/, concepts/, comparisons/, sources/, qa/)
- [ ] **WIKI-02**: `index.md` starts empty with correct section headers and format; Copilot fills it during first ingest
- [ ] **WIKI-03**: `log.md` starts empty with format specification; append-only, parseable with `grep "^## \["`
- [ ] **WIKI-04**: Every wiki page type has a documented format with required sections including `## See Also`
- [ ] **WIKI-05**: `raw/` is present with `.gitkeep`; immutability enforced by schema prohibitions

### Ingest Workflow

- [ ] **INGEST-01**: Ingest prompt file (`.github/prompts/ingest.prompt.md`) implements full ingest flow: read → check log → state takeaways → write source summary → create/update entity and concept pages → update index → append to log
- [ ] **INGEST-02**: Ingest skill (`.github/skills/wiki-ingest/SKILL.md`) implements the same workflow for CLI and Cloud Agent surfaces with specific trigger phrases in description
- [ ] **INGEST-03**: Both ingest artifacts handle edge cases: empty wiki (first-run), source already ingested (check log.md), source contradicts existing page (flag before writing)
- [ ] **INGEST-04**: Ingest saves URL content to `raw/<slug>.md` before processing (permanence)

### Query Workflow

- [ ] **QUERY-01**: Query prompt file (`.github/prompts/query.prompt.md`) reads index.md first, follows cross-links, answers with citations listing pages consulted
- [ ] **QUERY-02**: Query workflow includes the filing loop: after any useful multi-page synthesis, Copilot offers to file the answer as `wiki/qa/<slug>.md` and update index + log

### Lint Workflow

- [ ] **LINT-01**: Lint prompt file (`.github/prompts/lint.prompt.md`) checks for: orphan pages (in wiki/ but not in index), broken cross-links, missing `## See Also`, entities mentioned without their own page, stale claims, contradictions between pages
- [ ] **LINT-02**: Lint skill (`.github/skills/wiki-lint/SKILL.md`) implements the same checklist for CLI/Cloud Agent, with specific trigger phrases in description

### Librarian Agent

- [ ] **AGENT-01**: `librarian.agent.md` (`.github/agents/`) defines the librarian persona for Copilot CLI with full ingest/query/lint capability
- [ ] **AGENT-02**: Agent description field contains specific trigger phrases so Copilot CLI infers it correctly
- [ ] **AGENT-03**: Agent explicitly restricts writes to raw/ (tool restriction or instruction-level prohibition)

### CLI Intake Script

- [ ] **CLI-01**: `scripts/intake.sh` accepts a file path or URL argument and invokes `copilot -p "ingest <arg>" --allow-all-tools`
- [ ] **CLI-02**: Script includes a batch mode: when run with no arguments, scans `raw/` for files not yet listed in `wiki/log.md` and processes each
- [ ] **CLI-03**: Script is executable and works on macOS, Linux, and WSL (Windows targets)

### Fork-Ready Template

- [ ] **FORK-01**: `README.md` provides a 10-minute fork guide: fork repo → open in VS Code → enable prompt files → drop first source in raw/ → run ingest
- [ ] **FORK-02**: README includes the exact VS Code setting (`"chat.promptFiles": true`) and the CLI restart note for agents
- [ ] **FORK-03**: `copilot-instructions.md` uses `[YOUR DOMAIN]` placeholder comments in all domain-specific sections so fork users know exactly what to edit
- [ ] **FORK-04**: `TEMPLATE.md` documents the customization surface: what to change (schema domain sections, wiki placeholder pages), what to leave (ingest/query/lint logic, index/log format)

## v2 Requirements

### Search

- **SRCH-01**: Integration with qmd (local BM25/vector search for markdown) for wikis with 200+ pages
- **SRCH-02**: `wiki/search-index.json` generated by intake script for lightweight keyword search

### Publish

- **PUB-01**: `mkdocs.yml` config for generating a static site from wiki/ (GitHub Pages)
- **PUB-02**: Dataview-compatible YAML frontmatter on wiki pages (tags, source count, date)

### Hooks

- **HOOK-01**: `.github/hooks/audit-log.json` — pre-write hook that appends every file write to an external audit log
- **HOOK-02**: `.github/hooks/deny-raw-writes.json` — hook that denies any tool write to `raw/` at execution level

### Collaboration

- **COLLAB-01**: Multi-author workflow: pull request template for wiki updates with change summary
- **COLLAB-02**: `wiki/decisions/` directory with ADR-format pages (architecture decision records)

## Out of Scope

| Feature | Reason |
|---------|--------|
| RAG / vector stores / embeddings | Deliberate anti-feature — index.md pattern is the point; adding RAG negates the compounding value proposition |
| Obsidian Sync / real-time collaboration | Infrastructure dependency; git handles version control and collaboration |
| Automatic web scraping | Manual curation is by design — humans pick sources, LLM processes them |
| Content domains (ingesting Copilot docs, etc.) | Template is domain-agnostic; users bring their own sources |
| Claude-specific tooling (beyond existing .claude/) | This targets Copilot; Claude artifacts are secondary |
| Backend services, databases, hosted infrastructure | Everything must work in a cloned git repo with zero setup beyond Copilot |
| Copilot Memory as a dependency | Memory is off by default for orgs; wiki must work without it |
